# PR022 执勤余量紧张 · 备选方案演示

> 对应场景：飞机甘特机号 **B-30C8**，航班 **EU4629 兰州→太原**，机组 **夏云飞 / 任文博 / 苏林**，预计 FDP **13h30 / 14h00**（余量 **30** 分钟）。  
> 原先界面只出现「方案 A · 人工处理」。本目录给出可落地的预防性拆分换组，并附整表回测。

## 1. 为何原先只有「人工处理」

| 条件 | 本例实际情况 | 旧版求解器行为 |
|---|---|---|
| 已超 FDP | 否（余量 30 分，高风险但未超限） | 不生成「拆分换组@成都」 |
| 下游非过夜休息被压缩 | 否 | 不生成「后续任务换人」 |
| D4 是否从成都始发 | 否（首段兰州→郑州） | 即便超限也无成都拆分候选 |
| 面板文案 | 无 exceed 时默认写「下游休息不足」 | 易误解为已有下游问题 |

结论：不是「没法换人」，而是**触发条件过窄 + 文案误导**。末段 EU5281 预计晚到 +20 分后，D4 预计 FDP 恰为 13h30。

## 2. 推荐方案 A · 预防性拆分换组@兰州

**做法**

1. 原任务 **PR022** 保留 D1–D3（夏云飞 / 任文博 / 苏林），于 **D3 止于兰州过夜** 后结束本日后续执勤。
2. 自 **D4 首段 EU7321（兰州→郑州，11:10）** 起拆出 **PR022-B**（4 段）：
   - EU7321 兰州→郑州
   - EU7322 郑州→兰州
   - EU4629 兰州→太原（关注航班）
   - EU5281 太原→成都
3. 新机组（示例选人，工时均衡策略）：
   - **机长** 唐宇 **J3**
   - **副驾驶** 秦明轩 **F5**
   - **第三人** 蒋昊 **F7**

**合规要点（RE12 等）**

- 座位搭配：J3 + F5 + F7，副驾均 ≥F3，**无需**教员同组（避免 F1/F2 限制）。
- D4 航路无特殊机场授权要求；机型 A320；无血压测试仪始发提醒。
- 新机组经 `candidates` 校验：无时间冲突、休息/请假合规；应用后无人超 **90h**。
- FDP：PR022-B 预计仍为 **13h30/14h00、余量 30**，**不超限**；原组 D1–D3 余量充足。  
  （本方案价值在于：**原机组不再连飞该高压日**，风险从连续四日 pairing 上剥离；若运控要求进一步降 FDP，可再砍末两段或提前换组。）
- 异地换组：新机组须在兰州到位（过夜或 DH），方案卡片已注明。

## 3. 方案 B · 纯人工（对照）

取消/延后 EU4629+EU5281，或从成都 DH 整组至兰州。不自动改排班，供运控选择。

## 5. 求解器改进（已写入网页版）

高风险日（余量 &lt; 设置中的高风险阈值，默认 60 分）即使**尚未超限**，也会尝试：

- **预防性拆分换组@当日首段始发站**（本例为兰州）；
- 保留成都基地拆分（若存在）；
- 面板标题改为「执勤余量紧张（预防）」，不再误标「下游休息不足」。

请 **重置示例数据** 或清除本地缓存后，在执勤监控对 PR022 再点「生成处置方案」，应能看到多张非人工卡片。
