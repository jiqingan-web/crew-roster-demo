# 机组智能排班助手（路演演示版 · 示例数据）

纯 HTML/CSS/JS 单页应用，无构建、无外部依赖、完全离线。**直接双击 `index.html` 用浏览器打开即可**（推荐 Chrome / Edge）。
所有人员、任务均为程序生成的 **示例数据（SAMPLE）**，与真实人员、航班无关。

**编制（演示）**：空客一…八中队 + C909一…三中队（约 11×100 人）；任务由成都航司 **30 天甘特中 16 个完整日**真实机径模板（2026-09-30..10-07 与 10-13..10-20；跳过边界/空窗）按星期循环**铺满整月**（演示补全，非实飞；约 42 空客+16 C909、约 700+ 组任务）。自动填人将工时集中到典型飞行员约 **40–60h**，并洒 1–2 个培训日；支持导出全月班表 CSV 与个人月历 ZIP。特殊机场授权：J3/教员全授权，J2–US/新机长无授权，F7/F6 全特殊，F4+ 含拉萨。体检限制约 50 人（限-01…，无真实姓名）。**勿将** `真实航班表_*.xlsx` 或真实体检名单提交 GitHub。

## 功能
| 模块 | 说明 |
|---|---|
| 人员视图 | 甘特图：行=飞行员（员工号/姓名/级别/本月小时），列=2026年11月每天；任务条显示 D1..Dn 航线与时刻，如 `D1 成都-乌鲁木齐 08:00-12:20`，以及“机/副/三”机组；特殊机场红字；意向休息日、请假日以斜纹标示；悬停看详情，点击调整机组 |
| 任务视图 | 全部任务列表，可筛选 未满员/已满员/有违规/特殊机场，显示“始发站需血压测试仪”提醒 |
| 一键自动填人 | 启发式多轮求解（约 15–20 秒，视任务量），含休息节奏偏好与备份编排，带进度与结果摘要 |
| 手工调整 | 点任务 → 每个岗位下拉框仅列合规候选（按本月小时升序，⚠ 标注占用意向休息日）；不合规人员逐人列出原因（时间冲突、休息不足、请假、超 90h 法规上限、某航段无满足座位/特殊机场规则的组合、新机长缺教员等） |
| 校验报告 | 合规（各硬性规则违规数）、公平（各组工时区间/均值/标准差/基尼系数、每人工时柱状图）、合理（过夜、特殊机场暴露、夜航均衡、意向休息满足率）、覆盖率；节奏（任务天数分布、休息间隔分布、2–3 天占比、备份公平性） |
| 补位标记 / 补位历史 | 空洞换人或多方案「一键应用」后，在甘特条、任务列表、任务弹窗显示紫色「补位」角标；「补位历史」页列出请假人/补位人/任务/座位/时间，支持按步或整栈撤销 |
| 演示空洞 / 演示异常（路演） | 自动填人后默认近满员，并预留约 3–5 个**易补空洞**（1–2 天、无特殊机场任务的副驾位）供现场补位演示。【演示异常】默认**关闭**；设置中开启后至多植入 1 项（新机长缺教员座位硬违规）；正式/导入数据不注入 |
| 请假调配（临时请假 · 多方案） | 选人 + 日期区间（或在人员视图点击姓名、任务弹窗点“临时请假”）→ 即时（通常 <0.1 秒）生成 3–5 个方案卡片并排对比、综合评分排序、标“推荐”；悬停/点选卡片在影响预览中高亮；一键应用（跳回人员视图高亮变更）、一键撤销（保留历史，可逐步撤销） |
| 员工福利 | 每人 2 个意向休息日（示例已预填，可修改）；每日休息/请假人数按机长类、副驾驶分别限额（超限拒绝申报）；显示满足率 |
| 设置 | 最短休息、每日备份人数、每人每月最多备份天数、休息偏好权重、月小时目标下限/目标上限/法规硬上限、同日休息上限、报到/退场时间、血压测试仪机场、机场特殊类别 |
| 导入导出 | 导出排班表（逐航段含机组）、人员工时、问题清单、人员/任务数据、JSON 备份（UTF-8 BOM，Excel 直接打开）；导入人员/任务 CSV（提供模板）与 JSON 备份 |
| 存储 | 浏览器 localStorage；顶部“重置示例数据”一键恢复 |

## 已实现规则
**岗位**：每个任务 = 机（机长类：新机长/机长/教员）+ 副（副驾驶 F1–F8）+ 三（任意级别）。三人制下，**每一航段**只需三人中存在一组“左座+右座”满足以下全部规则，第三人观察，各航段可换座。

**RE12 座位搭配（左座 → 允许右座）**
- SPIC：仅 TL/TB/TC
- US / J0 / J1 / 机长A / 机长B：F4–F8 及任何机长/教员
- J2 / J3：F3–F8 及任何机长/教员
- TL/TB/TC：任何人
- F1、F2：机组中须有教员

**新机长（SPIC/US/J0/机长A/机长B）**：机组中须有 TL 及以上教员（求解器在新机长任“机”位时自动安排教员为“三”）。

**特殊机场**（需本人授权，红字显示；左右座两人都须持该机场授权）
- 拉萨 ZULS：两人均 J3 及以上
- 丽江 ZPLJ / 西双版纳 ZPJH / 西昌 ZUXC / 西宁 ZLXN / 大连 ZYTL：J2/J3 + F6 以上，或教员 + F5 以上
- 一般高原：迪庆 ZPDQ / 稻城亚丁 ZUDC / 九寨 ZUJZ：J2/J3 + F5 以上，或教员 + F4 以上
- 赤峰 ZBCF：J2/J3/教员 + F4 以上
- 克拉玛依 ZWKM：左座 J1 及以上；茅台 ZUMT / 吕梁 ZBLL / 忻州 ZBXZ：左座 US 及以上（这两类只限级别，不需授权）
- 延吉 ZYYJ：无额外要求
- A321 航段：左座须 J2 及以上

**时间与工时**：同一人任务不重叠；两任务间（末段落地+30 分钟 → 下一任务首段起飞前 60 分钟）休息 ≥ 12h（可配）；请假日不排；月飞行小时（轮挡时间）：**CAAC 月度硬上限 90h**（超出才算硬性违规）；不设目标上下限，自动排班按可用天数折算份额做公平均衡（基尼系数），并有削峰步骤压低离群高工时；上限可在设置中配置。

**血压测试仪机场**：部分本场/始发机场须配备血压测试仪。设置中勾选的机场作为始发站（出港）时，相关任务标记“需血压测试仪”（提醒级，示例为西安 ZLXY、乌鲁木齐 ZWWW；正式机场清单待确认，可在设置中随时调整）。数据字段为 `settings.bpTesterAirports`，旧版存档中的 `testerAirports` 会在加载时自动迁移。

**甘特图缩放与滚动**：人员视图右下角为浏览器式悬浮缩放控件「− 100% + ▾」：−/+ 按档位缩放（4%–160%，100% = 日视图 150px/天），点击百分比恢复 100%，▾ 菜单提供 日 / 3日 / 周 / 半月 / 整月·全局 预设；也可按住 Ctrl/⌘ 滚轮或触控板捏合缩放（以鼠标位置为中心）。“整月·全局”一屏显示全部飞行员与任务（行高、标签自动压缩，悬停查看详情）。甘特视口高度贴合窗口，底部横向滚动条常显（已用 ::-webkit-scrollbar 样式覆盖 macOS 默认隐藏的覆盖式滚动条），左侧姓名列固定，缩放控件不遮挡滚动条。

## 飞行节奏与备份（Standby）
- **示例任务**：以 3–4 天多日任务为主（约 80%），少量 1–2 天；每天 2–4 段（平均约 2.6 段/天），外站过夜，始终从 ZUUU 出发并回到 ZUUU。
- **示例人员结构（为洞填冗余而增配备员）**：教员 12（TC2/TB3/TL7）、J3 28、新机长 9、副驾驶 79（F8 3、F7 16、F6 14、F5 14、F4 10、F3 18、F2 3、F1 1），另含匿名体检限制演示人员（限-01…）。增加副驾驶与机长类备员后，自动填人可近满员，仅预留少量易补空洞。
- **休息间隔偏好（软约束）**：两任务间空闲 2–3 天最优；0–1 天、4 天、5+ 天逐级加罚（扣除意向休息日/请假日后计算）。12h 最短休息仍为硬约束。权重可在设置中调整。
- **备份**：贴近实际——每人每月至多 1 天备份（多数人当月为 0），每天 1 人（机长类/副驾驶交替，新机长不单独担任），全月约 30 人日；备份日须前后一天均无飞行任务。其余空闲日均为正常休息（不再因“连续空闲”插入备份）。每日人数与每人上限可在设置中调整；旧存档中的备份参数加载时自动迁移。甘特图中以琥珀色“备份”格显示。
- **临时请假多方案**（`RosterCore.leaveOptions`）：请假人仅从与请假日重叠的任务中移出，其余成员不动。方案类型：
  1. **调用当日备份**：任务日期内处于备份的合格人员，调用后撤销其备份日；
  2. **休息人员**（节奏最优 / 工时均衡 / 备选，候选人互不相同）：空闲、级别与全部规则合格、加上任务后不超过 90h 硬上限，尽量不占意向休息日；
  3. **链式调换**（≤2 层）：从另一任务调来合适人员顶替，再为该任务找合规补位；
  4. **兜底**：无合规解时标记“人工处理”，列出受阻规则（如拉萨须两名 J3+、新机长须 TL+ 教员、特殊机场授权、血压测试仪始发站）与候选人主要不满足项。
  - 多任务请假按时间顺序逐个任务组合，同一方案内人员不重复使用。不做同组调座。
  - 每张卡片列出：变更人员与任务（前→后）、每人月小时变化（≤90h 绿色；>90h 不会生成）、基尼系数变化、占用意向休息天数与节奏扰动、当日剩余备份、合规检查（座位搭配、特殊机场、休息/工时，硬性违规数）及血压测试仪提醒。
  - 综合评分（越低越好）= 未解决×1000 + 新增硬违规×500 + 超法规上限×200 + 占意向休息×25 + 节奏扰动×4 + 基尼增量×2000 + 链式层级×6 + 涉及人数×2 − 调用备份×5 + 备份清零日×3。

## 求解思路
1. 难度优先：含拉萨/特殊机场/A321 的任务先排，其余按时间顺序；
2. 每个任务从候选中组合“机/副/三”，逐航段验证合法性；评分 = 工时占比 + 休息间隔偏好代价 + 高低级副驾驶搭配 + 第三人优先副驾驶；
3. 意向休息日首轮严格遵守，确实排不满时才放宽（计入满足率）；
4. 局部搜索（单岗位替换）+ 交换搜索（高工时与低工时人员互换同岗位任务），同时考虑工时方差与休息间隔；
5. 释放“三”位上非必要的机长类人员给空缺任务，再补齐；剩余空缺尝试一步“置换链”；
6. 编排备份；
7. 以上整体做最多 5 轮随机扰动，取最优（硬违规 → 软违规 → 2–3 天休息占比 → 工时标准差）。浏览器中约 2–4 秒。

## 测试结果（默认示例，`node test/test.js`）
- 约 150+ 名飞行员（含备员与匿名体检限制样本）、约 150+ 个任务
- 自动填人后近满员（预留约 3–5 个易补空洞）；**无 FTL/座位硬违规**（未开启演示异常时）；软性极少
- 月飞行小时：全员 45.7–66.3h，均值 56.8h，基尼 0.031
  - 教员 57.7–63.6（均 60.2，σ1.8）；机长 J3 58.1–63.4（均 60.2，σ1.3）；新机长 45.7–54.1（均 52.2，σ3.0）；副驾驶 53.1–66.3（均 55.5，σ2.4）
- 任务间休息：344 个间隔中 2天 133、3天 84、4天 38、0–1天 49、5+天 40；**2–3 天占 63.1%**，均值 2.8 天
- 备份：共 30 人日（每天 1 人）；30 人各 1 天、70 人 0 天（机长类 0–1，副驾驶 0–1）
- 意向休息日满足 200/200 = 100%
- 请假调配测试：J3 请假 3 天，影响 2 个任务，其中 1 个由当日备份人员顶替，调配后硬性违规 0
- 多方案测试：机长 / 副驾驶 / 新机长 / 教员各请假两段任务，均在 <0.1 秒内生成方案，推荐方案应用后硬性违规 0、相关人员工时在范围内；工时上限压到 40h 时全部方案正确标记“人工处理”并给出受阻规则
- 其他 5 个随机种子：全部 0 硬性违规、满员 100%，2–3 天休息占比 54–65%，副驾驶最低工时个别种子到 41h

## 假设与限制
- 工时目标约为机长类 ~60h、副驾驶 ~55h；新机长因必须与教员同组（教员占“三”位），工时偏低（~52h）。进一步提高总量（>1900h）时贪心+局部搜索开始出现 1–2 个任务机长类无人可排，故示例取 1880h 目标。
- 0–1 天休息间隔仍约占 14%，5+ 天约 12%（多为月初/月末或与请假相邻）；“2–3 天”为软目标。
- 备份日仅作为“占用一天、不计飞行小时”的值班，未建模备份时段与报到时限；备份规则按日粒度。
- 月小时下限按可用天数折算（有请假者按比例降低）。
- 工时按轮挡时间计算；未建模值勤期、累计疲劳等 CCAR-121 FTL 细则，最短休息为单一可配参数。
- 未建模机型资格以外的个人资质；F1 仅作“须有教员”处理。意向休息日 / 请假同日上限只在申报环节控制。
- 机场列表、航班号、时刻、授权均为示意数据。浏览器数据键为 crewRoster.v2（旧版本数据不会沿用）。


## 执勤监控（FDP / 延误 / 超执勤处置）

**FDP 限制表（默认值，参考 CCAR-121 部非扩编机组，可在「设置」中按公司规定修改）**

| 报到时间（本地） | 1–4 段 | 5 段 | 6 段 | 7 段及以上 |
|---|---|---|---|---|
| 00:00–04:59 | 12h | 11h | 10h | 9h |
| 05:00–11:59 | 14h | 13h | 12h | 11h |
| 12:00–23:59 | 13h | 12h | 11h | 10h |

- FDP = 当日首段计划起飞前 60 分钟报到 → 末段落地；扩编机组可选统一限制（默认 16h，关闭）。
- **计划风险**：延误余量 = 限制 − 计划 FDP；<60 分钟 高、<120 分钟 中、其余 低（阈值可配）。任务视图「执勤风险」列与「执勤高/中风险」筛选、人员视图甘特条带 ⚠/◔/⛔ 标记与描边、校验报告「执勤风险」面板（含计划过夜休息 <10h 提示）。计划 FDP 超限记为硬性违规「执勤期超限」。
- **运营看板**：**饱和度 / 韧性度** 双轴大指标与四象限着色（理想/低效/警戒/高危，可按中队下钻）、**今日运营**条（未满员/高 FDP 风险/待补位/备份缺口）、**今日简报**一键复制或导出 txt；另含剩余运力、人机比、人均/单机轮挡、飞机利用率等；公式见页内与下文。
- **请假空洞换人**：空缺座位 + Top3 候选人合规灯（绿/琥珀/红）与影响芯片；多方案卡片仍保留。
- **人员总览**：特殊机场授权矩阵（与 RE12 需授权类一致）+ 健康限制（不适飞/限制高原/限制夜间/月≤Nh/非唯一机长/血压备注/体检到期）；可筛选、编辑、导出 CSV；校验中不适飞/体检过期/个人月飞行上限/非唯一机长（禁 C 位）为硬性，高原/夜航限制为软性。示例库含 26 名匿名「限-01…」体检限制演示人员（无真实姓名）。
- **执勤监控页（按实际/预计时刻滚动监控）**：顶部可切换 **任务卡片 | 飞机甘特**。飞机甘特按机号分行、横轴为当日时刻（可跨午夜）；航段色块按延误/FDP 风险着色（绿/琥珀/红），可筛选机号，右下角缩放；悬停看航班/航路/机组/计划与实际时刻/FDP 余量，点击条可编辑该段实际/预计时刻（与卡片视图共用 `actuals`）。 生成处置方案后，各方案卡片有「导出此方案」、面板有「导出备选方案」（导出当前选中或推荐方案）下载 JSON+CSV 备选摘要（含拆分 PR-B、机组前后、工时变化、FDP 修复情况），**不**改动当前排班；「一键应用」仍单独写入。示例数据每段均分配机号（如 B-32GV、B-32HC）。选日期，逐航段录入实际/预计起飞、落地（日期+时间，可跨午夜，状态 预计/实际）。预计 FDP = 报到 → 当日最晚的实际/预计落地；未录入航段按计划时刻，**前段延误不级联到后续航段**（可在过站追回）。若前段延误不追回、按最短过站 35 分钟顺延会超限，仅显示「ⓘ 若不追回将超限」提示（不计入超限）。每录入一段实际落地即重算超限、剩余余量（显示「已落地 n/m 段」）与过夜休息（<10h）及下一任务前休息（<12h）。「模拟」按钮只给风险最高任务的第 2 段设预计起飞/落地 +120 分。高风险未超限时也会生成「预防性拆分换组@当日始发站」（见 demo/方案演示.md，PR022 案例）。旧版 `delays`（分钟）在加载时迁移为该段自身的预计起飞/落地（`migrateDelays`）。
- **处置方案（3–5 张卡片）**：在成都基地出发的航段处拆分、由新机组接手（整组更换即在首段前拆分），新机组按 调用备份 / 节奏最优 / 工时均衡 / 链式 / 备选 生成；原机组受影响的后续任务一并补位；始终附「取消/调整超限航段（人工处理）」兜底卡并列出阻断原因。卡片含人员与任务前后、每人小时（≤90h）、基尼变化、意向休息、剩余备份、执勤/休息结果和合规检查；悬停预览、一键应用、与请假调配共享撤销历史。
- 示例场景（11/27 PR140 D1，报到 08:45，限制 14h00 至 22:45）：① 录入 EU2550 兰州-成都实际 16:45 起飞 / 18:10 落地（晚 240 分）→ 预计 FDP 仍按计划 12h20、剩余余量 100 分钟，另提示「若不追回将超限：EU8035 落地 23:05，超 20 分钟」；② 录入 EU8035 稻城亚丁-太原预计落地 23:05 → 预计 FDP 14h20，超 20 分钟，过夜休息压缩至 9h25 → 生成处置方案，推荐「拆分换组@成都 · 节奏最优」（自 15:45 成都起新机组执行 PR140-B，超限 0、硬性违规 0；若 EU8035 仍预计 23:05 落地，新机组过夜休息同样偏短，卡片会标出休息问题 1 项，需运控协调次日报到）。


## 运营看板公式

| 指标 | 公式 |
|---|---|
| 饱和度 | 已排飞行小时 ÷ Σ个人硬上限（小时口径，贴近「占用人天/可用人天」） |
| 韧性度 | Σ max(0, 个人硬上限 − 已排) ÷ Σ个人硬上限（可排冗余运力占比） |
| 四象限 | 理想：饱和 80–90% 且韧性 ≥10%；低效：饱和 <80%；警戒：饱和 >90%；高危：饱和 >90% 且韧性 <5% |
| 剩余运力 | Σ max(0, 个人硬上限 − 个人已排飞行小时)；个人硬上限 = min(公司月上限, 体检 maxMonthH) |
| 人机比 | 飞行员人数 ÷ 本月出现机号数 |
| 人均 / 单机轮挡 | 总轮挡小时 ÷ 飞行员数（或机号数） |
| 飞机利用率 | 总轮挡小时 ÷ (机号数 × 日历天数 × 日可用窗口小时)，窗口默认 14h（设置 `opsDayWindowH`） |
| 机日航段 | 总航段数 ÷ (机号数 × 日历天数) |
