01 · DIFF

同一项工作，两种工作流

旧方式靠填表、经验和群聊；新方式把规则写进引擎。

BEFORE

Excel / 旧系统

  • 填人逐格抠表，靠眼力对账
  • 规章口头提醒，事后翻账
  • 请假群聊喊人，方案难比
  • 回溯痕迹散落聊天记录
  • 压测不敢动 live
AFTER

规则运行时

  • 填人AUTOFILL 出可校验草案
  • 规章硬/软分列，点选定位
  • 请假多方案 + 合规灯
  • 回溯历史 / 补位痕迹可撤销
  • 压测深拷贝三场景，不改 live
工作流旧方式升级后
出草案按天手工抠分钟级可校验草案演示盘
找违规事后翻账即时硬/软分列 + 定位
请假补位群聊协商多方案 · 合规灯 · 空洞诊断
规章口径个人经验规则进引擎 · 结果可复跑
应对变化不敢动 live隔离压测 · 设置页复跑
解释结果难还原历史、痕迹、报告可追溯

「分钟级」为演示盘 / 路演口径，不作未验证生产工时承诺。

03 · CAPABILITIES

核心能力：痛点 → 证据

均为已实现能力；不编造算法名或未测指标。

A · AUTOFILL

一键自动排班

痛点
整月逐格填；休息 / 资质 / 工时交叉，排完仍不敢说硬规则过了。
场景
月度草案：导入空白表或重置示例后，要尽快出可校验初稿。
操作
一键排班 → 后台进度 → 甘特刷新 → 校验满员与硬违规。
能力
三人制座位、休息、特殊机场、新机长带教、帮扶≤1、模拟机占位、工时均衡；宁缺毋滥。
证据
演示盘 212 / 212 满员，硬违规 0（可复跑）。
价值
出草案从按天手工 → 分钟级可校验起点（演示盘体感）。
B · VALIDATE

规则引擎与即时校验

痛点
规章靠口头；硬伤与软提醒搅在一起，不知先修哪条。
场景
草案后、请假应用前、压测对照——任何要确认合规的节点。
操作
校验报告 → 硬/软分列 → 点击定位 → 换人 / 补位 / 自动纠错。
能力
三人制、特殊机场、新机长带教、帮扶≤1、模拟机、121.495(b) 第5日、休息与 FDP 等；硬阻断 / 软提示。
证据
基线硬违规 0；校验报告可在 lite 打开。
价值
事后翻账 → 即时定位；规章进统一引擎（公开页不作规章解释依据）。
C · LEAVE-REPAIR

请假补位

痛点
群聊喊人；方案难比，合规与工时说不清，难审计。
场景
运行日请假、同级转让 / 换班，需合规补空座。
操作
选人 → 多方案卡片 → 比合规灯 → 应用 → 留痕；可撤销。
能力
多方案、合规灯、空洞诊断、同级转让、历史撤销、补位痕迹。
证据
方案对比 / 应用高亮 / 补位历史截图；lite「请假调配」可复现。
价值
群聊协商 → 可比较、可合规、可审计的补位决策。
D · DIAGNOSE

空洞诊断

痛点
只知「排不满」，分不清数据问题、规则冲突还是运力不足。
场景
AUTOFILL 留洞、请假无候选、导入后固有冲突。
操作
打开诊断 → 看原因分类 → 强制指派 / 换人链 / 回修数据规则。
能力
区分数据 / 规则 / 运力；联动换人推荐与一键自动纠错。
证据
诊断与强制指派界面、自动纠错步骤均可演示。
价值
报错数量 → 下一步动作，缩短修复路径。
E · OPS 运营看板 饱和 · 韧性 · 今日 · 基尼 · 延误 F · STRESS 压力回测 不改 live · 三场景 G · QWEN 千问侧栏 解读结果 · Key 可选
04 · OPS

运营看板：看懂风险

饱和、韧性、今日风险、公平、资质、延误——收成一屏。

饱和度 · 韧性度

已排 ÷ 容量、剩余 ÷ 容量；四象限，可下钻中队。

今日运营

未满员、高 FDP、待补空洞、备份缺口；可导出简报。

执勤 · 延误鲁棒

FDP 余量滚动监控；+30 / +60 分钟冲击测处置空间。

公平性 · 资质

工时基尼、班型占比；体检到期、带教、特殊机场供需。

风险驱动韧性

晚→早连飞、过站偏紧、单点脆弱、空洞火花线。

指标来自 lite 已实现模块；无公开公式处不二次编造。

05 · STRESS

压力回测：先试哪里失守

不改 live，深拷贝预演多人请假、密度+30%、资质稀缺。

痛点
不敢动正式表做假设；密了 / 少了只能等爆再救。
场景
草案评审、运力规划、资质结构变化前的预演。
操作
设置页 → 跑三场景（或单跑）→ 结果写面板，live 不变。
能力
基线对照 + 请假 / 密度+30% / 资质稀缺；深拷贝后汇总。
证据
公开页不编通过率；数字以本机 lite 面板为准。
价值
不敢试 → 隔离试，更从容应对变化。
CASE 01多人请假集中请假冲击
CASE 02任务密度 +30%暴露运力瓶颈
CASE 03资质稀缺特殊机场授权收紧
06 · AI

千问侧栏：解读，不取代引擎

帮理解满员 / 违规 / 工时输出；决策仍以规则引擎与人工确认为准。

它做什么

  • 解读满员、违规、工时等结果
  • 用自然语言标出「先看哪里」
  • 协助理解校验与看板输出

边界

  • 不是不受约束的排班决策者
  • 不替代硬约束引擎与人工确认
  • 纯前端 DashScope；Key 仅存本机
  • Key 可选：无 Key 核心能力仍可跑
07 · PANORAMA

功能全景

已落地能力分组一览；细节见上文与 lite。

规则与座位
