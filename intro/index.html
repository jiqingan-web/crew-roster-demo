01 · DIFF

同一项工作，两种完全不同的工作流

旧方式依赖人工填表、经验校验和群聊协调；新方式把规则写进引擎，让草案可执行、违规可定位、补位可比较、压力可提前试。

BEFORE

Excel / 旧排班系统

  • 填人逐格抠表，跨表对不上靠眼力
  • 规章口头提醒，违规定位靠事后翻账
  • 请假群聊喊人，方案难并列比较
  • 回溯「当时为何这么排」散落聊天记录
  • 压测不敢动 live；密度一涨只能硬扛
AFTER

规则运行时 · RUNTIME

  • 填人AUTOFILL 在硬约束下出可校验草案
  • 规章硬/软违规即时分列，点选定位任务
  • 请假多方案卡片 + 合规灯 + 空洞诊断
  • 回溯方案历史 / 补位痕迹可撤销、可对照
  • 压测深拷贝三场景，不改坏当前 live

03 · CAPABILITIES

核心能力详解：从痛点到证据

每一项都按「痛点 → 场景 → 操作 → 能力 → 证据 → 管理价值」展开。以下均为仓库已实现能力，不编造算法名或未测指标。

A · AUTOFILL

一键自动排班：硬约束下的可校验草案

业务痛点
整月座位靠人工逐格填，休息、资质、工时均衡交叉约束多，排完也不敢说「硬规则过了」。
使用场景
排班员在月度草案阶段：导入航段空白表或重置示例后，需要尽快得到一版可校验的初始方案。
操作过程
点击一键自动排班 → 进度可后台跑 → 甘特刷新 → 再跑校验看满员与硬违规。
系统能力
三人制座位搭配、休息间隔、特殊机场授权、新机长须教员同组、帮扶对象同组至多一名、模拟机提前占位、工时均衡偏好等共同参与编排；遵循宁缺毋滥——宁留可诊断空洞，不硬塞出违规。
结果证据
演示盘基线：212 / 212 座位排满，硬约束违规 0（演示盘口径，可本机复跑）。
管理价值
把「出草案」从按天手工抠，收敛为分钟级可校验起点（演示盘体感），让后续校验与补位有稳固底座。
B · VALIDATE

规则引擎与即时校验：发现问题 → 定位任务 → 修复

业务痛点
规章靠经验口头提醒，出了问题事后翻账；硬伤与软提醒搅在一起，不知道先修哪条。
使用场景
草案生成后、请假应用前、压力回测对照时——任何需要「这一版是否合规」的节点。
操作过程
打开校验报告 → 硬/软违规分列 → 点击条目定位到任务/人员 → 进入换人、补位或自动纠错。
系统能力
引擎内可执行规则包括：三人制座位、特殊机场授权、新机长须教员同组、帮扶对象同组 ≤1、模拟机占位、121.495(b) 第5日口径、休息与 FDP 相关硬约束等。硬违规阻断、软违规提示；点击可跳转高亮。
结果证据
基线演示盘硬违规 0；校验报告可在 lite 演示中打开对照。
管理价值
把「事后翻账」变成「即时定位」；规章从个人经验进入统一引擎。公开页不作规章解释依据，细则以受控文本与局方规章为准。
C · LEAVE-REPAIR

请假补位：多方案比较 → 应用 → 留下痕迹

业务痛点
临时请假靠群聊喊人，方案难并列比较，合规与工时影响说不清，事后难审计。
使用场景
运行日有人请假、需同级转让或换班、需在合规前提下尽快补上空座。
操作过程
选择请假人员 → 系统生成多套方案卡片 → 比较合规灯与影响 → 应用选中方案 → 甘特写入补位痕迹；可撤销、可看历史。
系统能力
多方案卡片、合规状态灯、空洞诊断联动、同级转让/换班、方案历史可撤销、补位痕迹写入。
结果证据
界面留有方案对比、应用后高亮与补位历史截图；流程可在 lite「请假调配」复现。
管理价值
把群聊协商升级为可比较、可合规、可审计的补位决策；协同更快，复盘有据。
D · DIAGNOSE

校验与空洞诊断：区分数据问题、规则冲突与运力不足

业务痛点
只知道「排不满」，不知道是表有问题、规则互相打架，还是人真的不够。
使用场景
AUTOFILL 留下空洞、请假后无合规候选、导入航段后出现固有冲突时。
操作过程
打开空洞诊断 → 阅读原因分类 → 按提示做强制指派、换人链或回到数据/规则侧修正。
系统能力
区分数据问题 / 规则冲突 / 真实运力不足；联动空洞换人推荐与一键自动纠错（BFS 换人链）。
结果证据
空洞诊断与强制指派界面可在演示中打开；自动纠错步骤可见。
管理价值
把「报错数量」升级为「下一步动作」，缩短从发现问题到修复问题的路径。

04 · OPS

运营看板：从「排出班表」到「看懂风险」

排完不是终点。看板把饱和度、韧性、今日风险、工时公平、资质缺口和延误处置空间收成一屏管理语言。

饱和度 · 韧性度

已排小时 ÷ 容量、剩余可排 ÷ 容量；理想 / 低效 / 告警 / 危急四象限，可下钻分中队。

今日运营

焦点日未满员任务、高 FDP 风险、待补位空洞、备份缺口；可复制 / 导出今日简报。

执勤监控 · 延误鲁棒

按实际/预计时刻滚动看 FDP 余量；设置页可对每段做 +30 / +60 分钟冲击，统计仍合规的处置空间。

公平性 · 资质监控

全员工时基尼、各组离散度、周末/夜航/早班占比；体检将到期、新机长带教、特殊机场供需比。

风险驱动韧性

FDP 余量均值、晚→早连飞、过站偏紧、单点脆弱任务抽样；每日空洞火花线——帮助看见「今天哪里先失守」。

看板指标均来自 lite 已实现模块。无公开公式资料的计算细节不作二次编造。

05 · STRESS

压力回测：变化来了，系统会先在哪里失守？

价值不是「多一个测试按钮」，而是在不修改 live 排班的情况下，用深拷贝提前试多人请假、任务密度上升、资质稀缺时的失守点。

业务痛点
不敢动正式表做假设；任务一密、人一少，只能等爆了再救。
使用场景
月度草案评审、运力规划、资质结构变化前的预演；答辩与路演需要可复跑证据时。
操作过程
进入设置页 → 跑压力场景回测（或单跑请假 / 密度+30% / 资质稀缺）→ 结果写在面板，live 不变。
系统能力
基线对照 + 三场景：多人请假、任务密度 +30%、特殊机场资质稀缺；深拷贝后 AUTOFILL/校验汇总。
结果证据
本公开页不编造通过率或提升百分比。场景、方法与复跑入口如下；具体数字以你本机 lite 跑出的面板为准，。
管理价值
把「不敢试」变成「隔离试」——更从容应对任务密度与资质结构变化。

06 · AI

千问侧栏：帮助理解结果，而不是取代规则引擎

AI 用于解读满员、违规与工时等系统输出，降低理解成本；排班决策仍以规则引擎与人工确认为准。

它做什么

  • 解读满员率、违规条目、工时分布等结果
  • 用自然语言回答「这份草案哪里需要先看」
  • 协助理解校验与看板输出，加速沟通

边界（必须清楚）

  • 不是不受约束的排班决策者
  • 不替代硬约束引擎与人工确认
  • 纯前端调用 DashScope；API Key 仅存本机 localStorage
  • Key 可选：无 Key 时核心排班 / 校验 / 补位 / 压测仍可跑
  • 不虚构模型版本认证或未公开的隐私合规声明
